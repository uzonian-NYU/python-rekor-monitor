# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| Latest code on `main` | Yes |
| Older releases and tags | No |

Security fixes are applied to the latest code on `main`.

## Reporting a vulnerability

Please do not report vulnerabilities in public GitHub issues.

Use this repository's GitHub Security tab and select
**Report a vulnerability** to submit a private report.

If that option is unavailable, do not publish sensitive details.
Contact the maintainer privately using contact information on their
GitHub profile.

Include:

- A description of the problem and its possible impact.
- Steps to reproduce it.
- The affected version or commit.
- A suggested fix, if available.

Do not include real credentials, access tokens, or private keys.

## Response goals

- Acknowledge reports within three business days.
- Provide an initial assessment within seven business days.
- Coordinate disclosure with the reporter after a fix is available.

These are response goals rather than guaranteed deadlines.

## Scope

Relevant reports include problems involving signature verification,
Merkle proof verification, dependency security, and accidental exposure
of credentials.
